## Question

What technology do we use for the demo frontend that showcases the platform's functionality?

## Decision

A minimal React SPA bootstrapped with Vite, located in a `frontend/` directory. No routing library, no state management library, no CSS framework. The frontend is demo-only — it exists to visually demonstrate tenant isolation, message CRUD, and search.

Components: user picker (switch between seed users), conversation list sidebar, message thread with pagination, send message form, and search bar.

## Alternatives Considered

| Option | Pros | Cons |
|---|---|---|
| Vanilla HTML + fetch | Zero build, single file | Manual DOM manipulation scales poorly with interactivity (list updates, user switching) |
| Next.js | SSR, full framework | Massively overengineered for a demo |
| **React + Vite** | Minimal setup, component state handles interactivity naturally, looks professional | Small build tooling footprint |

## Rationale

The demo requires enough interactivity (conversation selection, message list updates, user switching, search) that vanilla DOM manipulation would produce more code than a React component tree. Vite provides zero-config scaffolding. No extras are added — this is not a production frontend.

## Invalidation Trigger

If the frontend becomes a production concern requiring SSR, routing, or a design system.
